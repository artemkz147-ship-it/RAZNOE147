# Lighter Telegram Trader

Первая безопасная версия торгового бота для Lighter с управлением через Telegram.

## Что уже есть

- Telegram-панель: **Старт / Стоп / Статус / Закрыть позицию / Сбросить блокировку**.
- Доступ к управлению только для одного `TELEGRAM_ALLOWED_USER_ID`.
- По умолчанию `TRADING_MODE=paper`: реальные ордера не отправляются.
- Paper-торговля использует официальный `lighter.PaperClient` и живой стакан Lighter.
- Автоматический поиск активного perpetual-рынка по символу вместо жёстко заданного market id.
- Стратегия v1: EMA 20/50 + RSI + ATR + объём на 15m + подтверждение тренда на 1h.
- Одна позиция одновременно.
- Размер позиции считается от расстояния до Stop Loss.
- Ограничения: риск на сделку, максимум риска в USDC, максимум номинала, плечо не выше ×2, дневной стоп по стоимости счёта.
- 30-минутный cooldown после сделки.
- SQLite-журнал событий и состояния.
- В LIVE после входа создаётся position-tied OCO-пара SL/TP. Если поставить защиту не удалось, бот делает best-effort reduce-only аварийное закрытие.
- При неизвестной позиции на live-счёте бот блокирует новые сделки вместо попытки «угадать», что делать.

## Важно

Это экспериментальный торговый софт, а не гарантия прибыли. До LIVE нужно прогнать paper-режим и посмотреть на фактическую статистику. Для LIVE лучше использовать отдельный Lighter account/sub-account только под этого бота.

Никогда не добавляй `.env`, API private key, seed-фразу или приватный ключ кошелька в GitHub. `.env` уже находится в `.gitignore`.

## Быстрый запуск PAPER

1. Создай Telegram-бота через BotFather и получи токен.
2. Узнай свой числовой Telegram User ID.
3. Скопируй `.env.example` в `.env`.
4. Заполни только:

```env
TELEGRAM_BOT_TOKEN=...
TELEGRAM_ALLOWED_USER_ID=123456789
TRADING_MODE=paper
```

5. Запусти:

```bash
docker compose up -d --build
```

6. Открой своего Telegram-бота и отправь `/start`.
7. Посмотри `/status`, затем нажми **Старт**.

Paper-режим не требует Lighter API private key.

## Локальный запуск без Docker

Требуется Python 3.12 и Git.

```bash
python -m venv .venv
source .venv/bin/activate        # Linux/macOS
# .venv\\Scripts\\activate       # Windows
pip install -r requirements.txt
cp .env.example .env
python -m src
```

## Параметры риска по умолчанию

```env
RISK_PER_TRADE_PCT=0.5
MAX_RISK_USDC=0.12
MAX_DAILY_LOSS_USDC=0.45
MAX_POSITION_NOTIONAL_USDC=5
MAX_LEVERAGE=2
MAX_OPEN_POSITIONS=1
MAX_SLIPPAGE=0.003
```

Бот **не увеличивает** рассчитанную позицию только ради минимального размера ордера биржи. Если биржевой минимум нарушит наш лимит риска, сделка пропускается.

## LIVE

LIVE намеренно заблокирован по умолчанию. Для него нужны отдельные параметры:

```env
TRADING_MODE=live
LIGHTER_NETWORK=mainnet
LIGHTER_ACCOUNT_INDEX=...
LIGHTER_API_KEY_INDEX=...
LIGHTER_API_PRIVATE_KEY=...
LIVE_TRADING_ACK=YES_I_ACCEPT_REAL_MONEY_RISK
```

После изменения конфигурации сначала открой `/status`. Автоторговля после запуска всё равно остаётся выключенной, пока ты вручную не нажмёшь **Старт**.

### Как работает защита LIVE

1. Сигнал проходит все фильтры.
2. Рассчитывается размер позиции по Stop Loss.
3. Вход отправляется market/IOC с ограничением проскальзывания.
4. Бот считывает фактическую позицию.
5. Создаётся position-tied OCO: Take Profit + Stop Loss.
6. При срабатывании одной стороны вторая отменяется на стороне Lighter.
7. Если шаг 5 завершился ошибкой, бот пытается немедленно закрыть позицию reduce-only и аварийно останавливает новые входы.

## Команды Telegram

- `/start` — панель управления.
- `/status` — состояние, баланс, стоимость счёта, дневная просадка и позиция.
- **Старт** — разрешить новые входы.
- **Стоп** — запретить новые входы. Уже открытая LIVE-позиция остаётся под биржевым SL/TP.
- **Закрыть позицию** — аварийный reduce-only market-выход.
- **Сбросить блокировку** — снимает аварийный halt только если состояние счёта не конфликтует с ботом.

## Автотесты

```bash
pytest -q
```

Проверяются как минимум расчёт размера позиции и базовые условия стратегии.

## Что делать дальше

Перед реальными деньгами нужно добавить длительный сбор статистики: число сделок, winrate, profit factor, max drawdown, результат после funding/slippage, а затем прогнать стратегию на нескольких рыночных режимах. Небольшая прибыль на коротком paper-периоде сама по себе ничего не доказывает.
